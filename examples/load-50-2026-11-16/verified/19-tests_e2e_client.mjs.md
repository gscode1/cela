### 1. Token lookup rejects valid whitespace-padded entries
- Verdict: CONFIRMED
- Severity (verified): low
- Location (verified): tests/e2e/client.mjs:32-35
- Duplicate of: none
- Reasoning: The server's `tokenAuthenticator` splits on `/[\n,]/` and `.trim()`s each entry (auth.ts:33-34), while the client does `line.slice(0, at) === who` on the untrimmed line, so `alice:x, bob:y` finds no token for bob (and CRLF-terminated lines leave `\r` on the token). The secret generated by deploy/gen-api-secret.sh is `alice:..\nbob:..` without padding, so the e2e suite is unaffected today; only hand-written specs trigger it.
