{{- if .Values.security.allowDirectSandboxEgress }}

WARNING: security.allowDirectSandboxEgress=true. A profile with networkMode "direct" gets sandboxes that reach the open
internet and DNS directly: no egress rule applies and nothing is audited (private, cluster, metadata and platform
addresses stay blocked). The pools pi-env-direct-pool* and the policy sandbox-direct-allow-egress exist for them. Anyone
who can write a profile can opt a session into that; direct is refused together with a repo, the onecli route and
credentialed MCP servers. Direct sessions are counted in GET /admin/status (directSessions) and marked in the console.
{{- end }}
{{- if not .Values.egressProxy.enabled }}

NOTICE: egressProxy.enabled=false, so the network cutover is off: every sandbox keeps DNS, the OneCLI gateway and the open
internet directly, as before the proxy existed, and no egress rule applies. Turn the proxy on to make it the only way out
of a sandbox (docs/network-policy.md, docs/decisions/0038-network-modes.md).
{{- end }}

WARNING: NetworkPolicies isolate sandboxes only if the cluster's CNI enforces them (Cilium, Calico, kindnet since kind
0.24; flannel alone does not). This chart cannot tell, so the orchestrator (shard 0) runs an isolation probe: a short-lived
Pod with the sandbox's labels tries the database, the orchestrator, the Kubernetes API, the OneCLI API and another
sandbox, and the result is enforced | not-enforced | inconclusive (unknown until the first run, shortly after start).
Without enforcement a sandbox can reach all of them. The probe only reports; nothing is blocked. Read the measured
state, never assume it:

{{- end }}
{{- end }}

Read the runtime and network-policy state (GET /admin/status; admin owner: {{ first .Values.api.admins }}):

  kubectl -n {{ .Release.Namespace }} port-forward svc/pi-ingest 8080:8080 &
  TOKEN=$(kubectl -n {{ .Release.Namespace }} get secret {{ .Values.api.existingSecret }} -o jsonpath='{.data.tokens}' | base64 -d | sed -n 's/^{{ first .Values.api.admins }}://p')
  curl -s -H "Authorization: Bearer $TOKEN" localhost:8080/admin/status

It lists, per shard, the configured and the observed runtime and networkPolicy, and the probe's detail (what it tried,
when, why). Run the probe again, for example after a CNI change (the orchestrator picks the request up within seconds):

  curl -s -X POST -H "Authorization: Bearer $TOKEN" localhost:8080/admin/status/probe

Check the orchestrators: kubectl -n {{ .Release.Namespace }} get deploy -l app.kubernetes.io/name=pi-orchestrator
