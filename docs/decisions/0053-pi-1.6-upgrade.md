# 0053: Pi 1.6.0, and what the upgrade cannot undo

Status: accepted, 2026-11-22. Follows [0033](0033-own-adapter-package.md) (adapter release before a Pi upgrade) and
[0048](0048-sandbox-image-tools.md) (`pi-env` in the sandbox image).

## Context

Pi 1.6.0 (2026-11-20) replaces 1.5.2 in `@earendil-works/pi-durable`, `pi-ai`, `pi-mcp`, `pi-env` and `chord`. Nothing
in cela needed a code change: it compiles unchanged. cela does not use `RunEndTask` (renamed `HookTask`), code mode or
the code-mode namespaces, and its tools return results, not parks.

## Decision

Pin everything to exactly 1.6.0, with `@gscode1/pi-durable-postgres` 0.4.0 (peer dependencies exact on Pi Durable and
Chord 1.6.0; released first, per 0033) and the 1.6.0 `pi-env` tarball and per-architecture binary checksums in both
sandbox Dockerfiles and `images/README.md`. What matters to cela in 1.6.0:

- **The storage format moves forward.** `pi.tool` is version 4 and `pi.generation` version 3, and a sleep may have no
  `until`. A 1.5.2 Harness opening that data blocks those tasks (`task_too_old`) and treats a sleep without `until` as
  due. **The upgrade is one way: rolling back past this commit needs a Postgres restore.** Take a backup before rollout.
  `test/pi-upgrade-resume.test.ts` opens JSONL storage written by a real 1.5.2 Harness, killed mid-tool-call, and
  shows 1.6.0 resumes it: the tool (replay `unsafe`) is not run again, its result is `interrupted`, and the run settles.
- **Orchestrator and both sandbox images roll out together**, and warm pools are recycled. The `pi-env` client (in the
  orchestrator) and daemon (in the image) are the same version; a mixed pair is untested. The daemon fix for output lost
  when a program exits with the link backed up (up to 64 KiB) only takes effect with the rebuilt images.
- **pi-ai changes that reach models cela already uses.** `openai-completions` sends the `developer` role only to
  `api.openai.com`; every other host, OpenRouter included, gets `system` (override with `compat.supportsDeveloperRole`).
  Socket errors (`ECONNRESET`, `EPIPE`, `ETIMEDOUT`) and "Connection closed." are retried. The Google adapters take a
  custom `fetch`, so Google calls can go through the OneCLI gateway (`docs/model-credentials.md`); cela does not
  configure that yet.
- **Deferred.** Signals, parked tools and gates are ADR 0054 (gscode1/cela#354). Fitting images to the model's limits
  (`pi-durable/images/fit`) needs an image processor in the sandbox and is a follow-up.

## Consequences

- Rollout order: backup, adapter 0.4.0 and orchestrator and images together, recycle warm pools. A rollback restores the
  backup and the old images, losing what ran in between.
- A run in flight during the rollout resumes as in the test above; a tool that was running is reported as interrupted.
- Tool-result `durationMs` now spans the tool task's first run to its result, crash downtime included; nothing in cela
  reads it for a limit.
- The next Pi upgrade repeats the adapter-first order of 0033.
